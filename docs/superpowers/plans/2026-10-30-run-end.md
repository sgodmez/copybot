# Actions de fin de run et plugins e-mail, webhook, archive — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** une liste ordonnée d'actions après chaque run de copie (conditions succès/erreur/annulé), `postProcess`
migré en action intégrée, un coffre local de secrets, et trois plugins : e-mail, webhook, archive ZIP + SHA-256.

**Architecture:** nouveau type d'action d'API `IRunEndAction` (étape `RUN_END`) recevant un `RunReport` construit par
le moteur à la fin du run ; `MainExecutor` exécute les actions dans l'ordre avec délai avant de publier le statut
final ; les références `${secret:…}`/`${env:…}` des configurations sont résolues avant `loadConfig` ; chaque plugin
est un module de `copybot-plugin`.

**Tech Stack:** Java 25 (JPMS, `java.lang.foreign` pour DPAPI), JUnit 5, Gson, JavaFX 25, picocli, Jakarta Mail +
Angus Mail (plugin e-mail), `java.net.http` (webhook), `java.util.zip` (archive).

**Spec:** `docs/superpowers/specs/2026-10-30-run-end-design.md`.

## Global Constraints

- JDK 25 ; `mvn -q verify -pl <module> -am` par module, `mvn -q verify` à la racine en fin de plan.
- API des plugins **1.2, non publiée** : ajouts seulement, sans changement de version ; empreinte régénérée avec
  `-Dplugin.api.update=force` (le contrôle exige une montée mineure pour tout ajout ; la 1.2 n'étant pas publiée, les
  ajouts y entrent) — vérifier que le diff de `plugin-api.txt` ne contient que des lignes ajoutées.
- Bundles ASCII + `\uXXXX` ; clés du moteur en en/fr/it (le bundle moteur italien existe depuis le plan des suites) ;
  clés UI en en/fr/it ; bundles des nouveaux plugins en en/fr/it.
- Pas de nouvelle dépendance dans le moteur ni l'IHM ; les bibliothèques des plugins restent dans leur module.
- Un commit par tâche, message en anglais, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Valeurs fixées : `when` par défaut `["success","error"]` ; délais par défaut post.process 30 s, e-mail/webhook 60 s,
  archive sans limite, `0` = sans limite ; coffre `%APPDATA%\Copybot\secrets.json` / `~/.config/copybot/secrets.json` ;
  e-mail : port 587, `starttls`, `details` = `errors`, 200 lignes max ; archive : `SHA256SUMS` au format `sha256sum`.

## Review Focus

1. Pipeline existant avec `postProcess` : même programme lancé, mêmes arguments, mêmes conditions (succès, erreur),
   rien de lancé sans répertoire créé — test dans la tâche 2.
2. Run planifié qui échoue avant la copie (source absente) : l'action « erreur » part quand même — tâche 3.
3. Secret absent ou indéchiffrable : refus clair, aucune valeur dans les journaux ni dans le pipeline enregistré —
   tâche 4.
4. Action qui bloque (SMTP injoignable) : le run se termine au délai, avertissement, les actions suivantes passent —
   tâche 3 (et 7).
5. Archive interrompue : aucun fichier partiel laissé sous le nom final — tâche 8.

### Task 3: Déroulé de la fin de run dans le moteur

**Files:** `MainExecutor` (et les classes extraites par le plan des suites : `RunArchives`, `ListingPipe`),
`CopybotEngine` (chemin du pipeline), `ItemRunner`/`WorkItemExecution` (fin d'un élément : écrit + cible, sauté par la

et `RunReports` (construction du bilan), `PipelineState.getRunEndStep()`, bundles moteur. Tests :
`MainExecutorRunEndTest`, `RunReportsTest`.

- Résolution des étapes de fin **avant** les autres ; exécution aux moments de la spec § Déroulé (copie, une phase,
  continu, auto, échec pendant la préparation d'un run lancé pour copier, annulation) ; jamais après une préparation
  du mode plan ; statut final publié après les actions.
- Chaque action dans un fil virtuel, `Future.get(délai)`, interruption au délai ; `RunEndContext.publish/warn` ;
  `outputs` cumulés ; `cancel()` pendant la fin de run : interrompt l'action en cours, saute les suivantes.
- Tests : ordre et conditions (succès/erreur/annulé) ; action qui lève ⇒ avertissement, la suivante tourne ; action
  qui bloque ⇒ délai, avertissement, run terminé (Review Focus 4) ; `publish` visible par la suivante ; échec de
  préparation d'un `run` (dossier source absent) ⇒ action « erreur » appelée avec `failure` (Review Focus 2) ;
  préparation seule ⇒ rien ; bilan : compteurs, `items` sans les éléments du point de reprise, `FILTERED`,
  `writtenFiles` avec les compagnons, `copyStarted` ; `getRunEndStep()` renseigné pendant l'action.
- Commit : `Engine: run-end actions after a copy run, with the run report`.
